## Context

生产分支使用 Go/Gin/Ent、Vue 及 MySQL，同时保留 PostgreSQL 迁移。已有用户余额、API Key 鉴权/计费缓存与按用户分组授权的渠道监控。参考仓库的核心 QQ 模块使用官方 QQ 接口与 PostgreSQL SQL；本次按普通 QQ + NapCat 路线独立实现。

## Goals / Non-Goals

**Goals:** 完成连接、绑定、余额、签到、渠道状态、聊天与管理界面；资金变更具备数据库级幂等与事务保证。

**Non-Goals:** 本次不增加转账、抽奖、邀请返利、自然语言修改余额或机器人登录站点管理账号的能力。

## Decisions

1. OneBot v11 反向 WebSocket 由 Sub2API 接收，使用独立访问令牌及配置中的机器人 QQ 校验；只处理群白名单内的群聊消息。以原生消息段识别 @机器人，固定指令也支持明确命令前缀。配置关闭或凭据改变后终止旧连接。
2. 新增独立 qqbot 包，使用仓库接口隔离数据库；宿主 service 适配余额缓存与渠道监控，聊天通过固定的本机网关地址执行，不允许模型调用任意站点或管理接口。
3. 绑定码由已登录网站用户生成，数据库仅保存摘要且五分钟过期。QQ 发送后只暂存待确认身份，用户在网站看到该 QQ 并确认才建立绑定。QQ 与站点用户均唯一；解除绑定只能由网站用户本人或站点管理员操作。
4. 每个事件以机器人 QQ、群号、消息 ID 去重。签到使用北京时间自然日，锁定当前配置、绑定及用户行；奖励唯一键按用户和日期生成，入账与记录在同一事务。更换 QQ 或换群不能重复领取。余额缓存只在提交后失效。
   奖励支持固定金额或后台上下限之间随机金额，精度为 8 位小数；随机数与入账流水一起落库。重复签到读取该用户当日原流水金额，不重抽、不重复入账。
5. 机器人聊天使用运营方配置的专用站点 API Key，通过现有网关完整鉴权和计费。绑定用户的余额只因签到增加，不因共用机器人聊天扣减。设置单人每日限额、全站每日限额、冷却时间、上下文长度和输出长度；消息历史按群和 QQ 隔离。
6. 渠道状态必须由提问者当前绑定账号的可见分组与已有监控配置共同限定，只返回名称、聚合成功率和延迟，不返回账号、密钥、上游错误正文或其他用户信息。
7. 后台配置对令牌和 API Key 采用现有 SecretEncryptor 加密，读取仅返回已配置标志；留空保存保留原值，清除须显式操作。连接测试只验证连接/模型，不发奖励。
8. 新建管理员 QQ 机器人页面与个人资料绑定组件，复用当前权限、布局、样式和 i18n。默认关闭模块和奖励，在填写群白名单、机器人 QQ 与令牌前不能启用。

## Risks / Trade-offs

- NapCat 登录、掉线及 QQ 风控由协议端负责 → 管理页展示连接状态，部署文档明确需要账号持有者扫码。
- 同一消息重投或多次签到 → 事件去重和用户/日期奖励唯一键双重保护，数据库事务回滚不留半笔入账。
- 模型提示词注入或群成员冒认身份 → 业务命令在模型外执行，身份仅取可信 OneBot 事件，模型不拥有财务工具。
- MySQL/PostgreSQL 差异 → 双份无 BOM 迁移，SQL 由 Ent dialect builder 生成；覆盖真实事务SQL和重复请求路径测试。
- 外部聊天调用失败 → 已发起请求的每日聊天次数仍消耗，避免以失败重试绕过额度；不自动重发可能已计费的生成请求。

## Migration Plan

先在隔离开发分支完成双数据库迁移、后端、页面与测试，再推送构建。新版本默认关闭机器人与签到，不影响现有接单。回滚使用上一镜像，保留新增表和已发奖励记录，不回滚用户余额。实际 QQ 群验收需要机器人账号登录及群号配置。

## Open Questions

用户已确认普通 QQ + NapCat／OneBot，聊天统一使用站点专用 Key、由站点承担费用。签到金额与聊天模型由后台配置，不预置真实发奖或模型调用凭据。
