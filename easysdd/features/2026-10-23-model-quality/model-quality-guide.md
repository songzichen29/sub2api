# 分组降智检测（糖果本地核对与鹈鹕模型裁判）

管理员配置入口：**渠道监控 → 降智检测**。管理员和用户都可从对应渠道的**降智状态**方块打开结果。

## 配置和使用

1. 在渠道监控中配置并启用要检测的 OpenAI 渠道。该渠道须有有效 Key、公网 HTTPS 地址且支持 Responses 接口。
2. 新建检测计划，选择**绑定渠道**，无需重复填写 URL 或 Key。使用本站 Key 时自动识别并锁定实际分组；外部渠道 Key 则选择结果归属的分组。每次检测读取渠道最新的 URL 和 Key，地址按渠道监控约定补齐 `/v1`。
3. 包含鹈鹕检测时，为计划创建者准备唯一命名为 **测试降智** 的本站 API Key，绑定可调用裁判模型的分组。在计划中选择**评分模型**，也可搜索并填写自定义模型名；默认 `gpt-6.1-sol`，每个计划独立保存。该 Key 与被测渠道 Key 是两个角色，可以使用不同分组。
4. 选择糖果或鹈鹕模式、请求模型、思考强度和服务等级。纯糖果计划点击**保存**，不需要裁判 Key 或评分模型，也不发起评分探测。包含鹈鹕时点击**测试并保存**。后端会先用选中的评分模型实际请求一次评分，响应完整且结构有效才写入配置；失败保留填写内容和原计划。默认不启用定时检测；点击“立即检测”可手动执行。定时间隔范围为 3 分钟至 7 天；同一计划可配置最多 100 个模型、模式、强度和服务等级组合。
5. 需要用户看到结果时，开启“向有权限使用此分组的用户展示”。普通用户的列表、历史和详情都会校验分组权限。
6. 渠道卡片显示最近 60 轮已完成检测，左旧右新；一轮全部组合完成后才显示方块。绿色为正常，黄色为疑似降智，检测异常、取消和无法判定为灰色。没有记录时不填充模拟方块。
7. 点击方块可分别查看本轮和历史结果，按模型、检测类型切换，每页 12 条。拖动“结果卡片大小”可调整一排的数量，单张可放大。
8. 糖果回答按安全 Markdown 展示，本地核对结果不显示裁判模型、置信度或裁判用量；鹈鹕提供 HTML 预览与源码切换。旧自由创作历史仍可查看。判定来源、具体分项证据、裁判模型、证据置信度和生成/裁判 Token 用量收纳到“详情”。置信度不是经验证的准确率。历史保存在本站数据库中。

两种模式均不调用 Manxue。本站直接向绑定渠道的 `/v1/responses` 发送固定测试题，糖果在本地核对答案，鹈鹕再使用裁判 Key 请求本站网关。生成和鹈鹕评分分别按正常规则计费，糖果核对不产生裁判用量；裁判能读取本次测试回答/HTML，不会收到既有用户对话或被测渠道凭据。裁判 Key 不会发送给被测外部渠道。两个 HTTP 客户端都禁止重定向及环境代理；外部生成请求使用监控已有的 DNS/IP 安全检查。计划只保存渠道引用，不在公开配置和结果接口返回密钥、内部凭据指纹或裁判 Key ID。

服务端可用 YAML 或同名环境变量设置（部署方式需要把变量实际传入应用进程）：

```yaml
model_quality:
  judge_key_name: 测试降智
  judge_model: gpt-6.1-sol # 新计划及未选评分模型的旧计划的默认值
```

对应 `MODEL_QUALITY_JUDGE_KEY_NAME` 和 `MODEL_QUALITY_JUDGE_MODEL`。计划已选择的模型优先于服务端默认值；空值旧计划继续使用默认值。模型固定写入每次运行快照，不会在失败后自动换模型重试。裁判地址固定为当前应用端口的 `http://127.0.0.1:<server.port>/v1`，要求应用监听 loopback 或通配地址；不能用表单指定外部裁判 URL。Key 必须属于计划创建者，精确同名且唯一，并满足正常网关的 IP、分组、余额和订阅等校验。

鹈鹕保存前测试使用固定公开 HTML 样本，复用正式评分的请求参数、JSON 契约和解析器；不生成新作品、不加入检测队列、不改写历史。测试最多等待 2 分钟，会按正常调用规则产生用量；检测服务不自动重发，网关重试规则不变。页面在测试时禁止重复提交、修改和关闭，同一应用进程还会阻止同一用户并发测试。测试期间 Key、绑定分组或状态发生变化时不保存。仅关闭已启用计划且不更换评分模型时跳过测试，避免评分线路故障阻止停用；运行中计划仍需先取消并等待结束才能编辑。

模型建议列表来自同一裁判 Key 的 `/v1/models`，读取失败不阻止手动选择。列表中的模型不一定可调用；包含鹈鹕的计划保存前用实际评分验证；纯糖果计划跳过。测试只证明当前请求和结构可用，不证明模型评分准确、各模式均表现稳定，或未来不会遇到限流和上游故障。更换裁判后，近 24 小时统计可能混合不同裁判的判断，应结合结果详情中的模型快照解释。

裁判不绑定上游账号，也不维护单独的账号可用性名单。账号选择、停用、限流与故障切换由本站网关负责；收到有效评分后，不因落到不同账号而拒绝结果。仅有模型名称不能代替有效授权或实际评分：网关最终未返回可用响应时，仍是检测异常，不是降智。

这里绑定的是**渠道监控**中已有 URL 和 Key 的记录；**渠道管理**中的渠道用于定价和模型映射，本身没有连接凭据。旧版填写本站 URL 和 Key ID 的计划仍可运行，编辑时可改为绑定已有监控渠道。

## 模式和判定含义

固定测试题与鹈鹕评分规则在 `backend/internal/service/model_quality_prompts.go`，题目版本为 `native-v1`；糖果本地答案核对在 `model_quality_candy.go`。鹈鹕裁判使用 Responses 结构化 JSON 输出，本站再次验证结构及分项 ID 后计算判定，不直接采用模型自由文本中的“正常”结论。鹈鹕输出兼容契约为 `json-v2`，判定策略为 `verdict-v2`，新评分的 `assessment.version` 为 `native-v1:json-v2:verdict-v2`。

输出契约同时写入请求的结构化格式参数和裁判指令，降低兼容线路忽略格式参数的影响。解析接受完整 JSON 外层的空白、BOM、单个 JSON/无语言代码围栏；忽略额外元数据，不保存、不采用其中的账号状态或自称结论。仍要求置信度、理由和全部分项证据有效；拒绝多个结果、重复 JSON 字段（包括大小写变体）、重复评分项、缺失/越界分数及残缺输出，不从任意说明文字中猜取 JSON，不替裁判补分。

| 模式 | 评分依据 | 特别注意 |
| --- | --- | --- |
| 糖果 `candy` | 本地核对明确最终答案是否为 21，不评价证明 | 支持常见 Markdown、公式及中文数字；错误答案不通过，无法识别或歧义为无法判定，不能只在正文中包含 21 |
| 鹈鹕 `pelican` | 鹈鹕形态、自行车结构、骑行连接、运动关系、完整性 | 分析坐标和变换；不按代码长度、JS 有无或配色判断 |

自由创作已停用，不能新建或执行；旧结果保持原样，仍可查看。旧计划需移除该模式后保存。

两种模式均可自定义被测模型，支持表单中的 low/medium/high/xhigh/max/ultra，但具体强度和服务等级必须由目标渠道支持。艺术模式不再硬编码只允许 gpt-6-astra。艺术裁判分析的是 HTML 源码，**没有实际运行浏览器或查看动画截图**；运行时不确定性不得冒充已证实的缺陷。用户手动预览不等于裁判已看过画面。

糖果新结果使用 `assessment.basis=answer_exact`、版本 `native-v1:answer-exact-v1`，仅保留 `answer` 分项；明确答案 21 显示“正常”，明确其他答案显示“疑似降智”，不完整或歧义结论显示“无法判定”。鹈鹕每项评分 0/1/2 分，分别代表明确核心错误、部分满足或证据不足、充分满足。置信度至少 0.8 且有核心项 0 分时显示“疑似降智”；全部核心项为 2 分时显示“正常”，其余显示“无法判定”。这些是保守的初始规则，尚未经人工标注集校准，不代表准确率。

任务 `succeeded` 仅表示生成和判定完成，不代表通过。API 错误、超时、结构不合法和残缺输出显示“检测异常”，不会当作降智。近 24 小时通过率沿用 `正常数 / 全部已结束检测数`，因此异常、取消和无法判定也在分母中；它不等于模型能力准确率。

历史 Manxue 判定不会被覆盖。原生版题目和裁判契约已变更，不能直接比较升级前后通过率。近 24 小时统计仍按配置聚合，切换期间可能混合两种来源，页面会提醒查看来源。

已有计划不能更换分组及已绑定的监控渠道；空闲时可修改模型组合，历史记录保留原快照。渠道 URL/Key 更新在后续生成时生效。作品已生成并脱敏保存后，即使被测渠道停用、不可读或凭据变更，也不阻断独立评分；此时只验证裁判 Key 和模型，不重新读取被测渠道凭据。本站网关继续负责模型映射、账号选择及兜底；外部渠道遵循其自身路由，归属分组用于展示和权限。配置快照并不是最终命中账号的证据。裁判与被测渠道若共享上游，会产生相关故障及偏差风险，建议使用独立稳定的裁判线路。

## 执行与持久化

- MySQL 迁移 `104_model_quality_monitor.sql` 创建计划和运行记录表；根目录 `246_model_quality_monitor.sql` 保留 PostgreSQL 迁移镜像。当前应用初始化使用 MySQL。
- 原生升级复用现有 JSON 列保存版本、评分和内部裁判 Key ID；计划级评分模型保存于 `config_json.judge_model`，不需要新增 SQL 迁移。
- 数据库锁定计划行后创建一轮多组合记录；同一计划同时最多一轮未结束任务。运行中的计划不能修改。
- 两个后台工作线程按租约领取任务。糖果生成后直接本地核对并结束；鹈鹕分“生成”和“评分”两个持久化阶段，每阶段至多发起一次 HTTP 请求，生成完成后先保存作品，再领取评分阶段。
- 请求前写入 `submitting` 和长于请求超时的租约。重启遇到不确定的在途请求时标记异常，不自动重发。已保存生成作品且尚未提交评分时，糖果直接本地核对，鹈鹕继续评分。HTTP 错误也不由检测服务自动重试；网关自身的重试策略不受此变更影响。
- 生成超时 8 分钟、评分超时 2 分钟；首次实际执行后超过 12 分钟停止。每两秒检查取消及租约变化，取消时中断本地请求，但上游已经发生的用量仍可能计费。队列等待不冒充生成耗时。
- 升级前已提交到 Manxue 的未完成任务标记异常，不再查询或取消远端，也不会重新生成；远端可能继续运行及计费。旧的排队但未提交任务按新规则执行；已结束历史不变。
- 生成前重新读取渠道凭据，检查渠道启用状态及协议；若 Key 属于本站，核对实际分组、状态、过期与限额。旧版计划继续校验 Key 所有者。评分阶段使用已保存的脱敏作品和裁判 Key，不依赖被测渠道的实时状态。裁判授权被移除、IP 限制、订阅或余额不足等仍由正常网关拒绝，不绕过现有校验。
- 使用当前请求持有的凭据脱敏返回正文、HTML 和评语，再写入数据库。裁判异常保留已生成的脱敏作品；只返回安全的 HTTP 状态，不回显上游错误正文或 URL。
- 评分格式校验失败时保留已取得的裁判 Token 用量，并记录固定的具体错误类别（字段类型、缺少置信度、评分项缺失/重复、分数越界、证据缺失等）。不记录未经审核的裁判原文或 JSON 异常中的任意字段名，避免回显密钥；该改动不能恢复旧失败记录中未保存的评分正文。
- 只保存已知的结果字段并脱敏；不公开远端任务能力 ID。源码始终作为文本展示。页面预览保留 CSS、SVG 和内联绘图脚本，放入仅允许脚本、没有同源权限的 sandbox iframe；保留 SVG `<use>` 对当前文档图形的复用（`href="#id"`、`xlink:href="#id"`），避免车轮、云朵等图形丢失，同时移除两种属性中的外部引用。预览会测量完整 HTML（包括页脚）并等比缩放到卡片区域，隐藏 iframe 内外滚动条；不会把内容裁成只有上半部分。过滤外部脚本、嵌套页面、表单和跳转链接，并用独立 CSP 禁止网络请求。外部 CDN 依赖不会加载。内联脚本沿用当前页面 nonce 以兼容生产 CSP，不能读取本站登录态或 DOM。
- 记录目前持续保留，不自动删除。停用计划可停止后续定时检测，已有记录仍可查。

## API

管理端（已有管理员认证和审计中间件）：

- `GET /api/v1/admin/model-quality`：计划及最近 60 次、累计统计、关联的监控渠道 ID。
- `GET /api/v1/admin/model-quality/options`：分组和可绑定监控渠道的非敏感选项，以及 `default_judge_model`、`judge_models` 和可选 `judge_models_warning`；模型列表最多等待 8 秒，不返回 URL 或 Key。
- `POST /api/v1/admin/model-quality`、`PUT /api/v1/admin/model-quality/:id`：新建、修改，接受计划级 `judge_model`（最多 200 字节，不含控制字符）。纯糖果计划忽略并清空裁判模型，直接持久化；包含鹈鹕的计划须后端测试通过，不能绕过表单直接保存未测试模型，上述关闭计划例外不发起测试。自由创作配置返回模式已停用。旧客户端省略该字段时保留已选模型或采用默认值。前端请求超时为 150 秒。
- `POST /api/v1/admin/model-quality/:id/run`：创建检测，HTTP 202。
- `GET /api/v1/admin/model-quality/:id/history?page=1`：每页 50 条历史摘要。
- `GET /api/v1/admin/model-quality/groups/:groupID/history?page=1`：同组各计划合并的历史摘要，每页 50 条。
- `GET /api/v1/admin/model-quality/groups/:groupID/results?benchmark=pelican&page=1`：按检测类型筛选后分页的完整卡片结果，每页 12 条；包含有权查看的类型列表和 `has_more`。网格一次请求一页，避免逐卡查询。
- `GET /api/v1/admin/model-quality/:id/results`：按 `batch_id` 或 `exclude_batch_id` 选择本轮或历史，支持 `model`、`benchmark`、`page` 筛选。
- `GET /api/v1/admin/model-quality/runs/:id`：完整结果。
- `POST /api/v1/admin/model-quality/runs/:id/cancel`：请求取消，HTTP 202。

用户端提供 `/api/v1/model-quality` 下对应的列表、历史和详情 GET 接口；无创建、修改、运行和取消权限。

## 验证范围

自动测试使用模拟 Responses 客户端/HTTP 服务与数据库桩，覆盖糖果本地核对、鹈鹕评分、自由创作停用与历史兼容、JSON/SSE、重定向/SSRF、响应限制、评分结构、Key 所有权与同名歧义、渠道凭据继承与轮换、已生成作品不再检查被测渠道、不同模拟上游账号返回有效评分、格式兼容与歧义拒绝、取消/租约失效、失败和重启不重复计费、历史兼容及前端证据安全显示。它们不证明真实裁判线路可用，也不证明判定准确。

计划级选模测试覆盖：保存前实际评分、失败不写入、新旧计划默认值、权限/忙碌/无效配置提前拒绝、停用例外、Key 轮换、并发和取消、JSON 持久化与排队时过期模型快照拦截、列表去重/限制/隐私，以及前端选模、自定义输入、测试中锁定和失败保留内容。此次功能验证没有使用线上 Key 产生额外调用。

2026-10-31 最初真实验证：使用指定的“测试降智”Key 调用 Luna 六次、6.1-sol 一次，均收到网关 HTTP 502；运维日志显示上游账号 4595 返回 403 `Upstream access forbidden`。当时未取得成功裁判评分。

2026-11-01 只读复核：线上已运行 `e12f246f9` 原生版；升级后的查询快照共56次，52次成功、4次评分结构异常。4次异常的裁判请求均命中4589，该账号同时有16次成功，因此不能仅凭账号身份判失败，也不能认定所有错误都是账号不可用。旧实现未保存失败评分正文，无法确认每次是哪个字段出错。此处 `json-v2` 兼容与阶段解耦属于后续本地修复，不代表已部署或已完成线上复测；历史结果不改写，阈值仍未校准。详细历史依据、反例与后续验收见 [原生检测历史分析](native-assessment-analysis.md)。
