# 分组降智检测（本站原生生成与模型裁判）

管理员配置入口：**渠道监控 → 降智检测**。管理员和用户都可从对应渠道的**降智状态**方块打开结果。

## 配置和使用

1. 在渠道监控中配置并启用要检测的 OpenAI 渠道。该渠道须有有效 Key、公网 HTTPS 地址且支持 Responses 接口。
2. 新建检测计划，选择**绑定渠道**，无需重复填写 URL 或 Key。使用本站 Key 时自动识别并锁定实际分组；外部渠道 Key 则选择结果归属的分组。每次检测读取渠道最新的 URL 和 Key，地址按渠道监控约定补齐 `/v1`。
3. 为计划创建者准备唯一命名为 **测试降智** 的本站 API Key，绑定可调用裁判模型的分组。默认裁判为 `gpt-6.1-sol`，也支持在服务端配置为 `gpt-6-luna`。该 Key 与被测渠道 Key 是两个角色，可以使用不同分组。
4. 选择模式、请求模型、思考强度和服务等级。保存默认不启用定时检测；点击“立即检测”可手动执行。定时间隔范围为 3 分钟至 7 天；同一计划可配置最多 100 个模型、模式、强度和服务等级组合。
5. 需要用户看到结果时，开启“向有权限使用此分组的用户展示”。普通用户的列表、历史和详情都会校验分组权限。
6. 渠道卡片显示最近 60 轮已完成检测，左旧右新；一轮全部组合完成后才显示方块。绿色为正常，黄色为疑似降智，检测异常、取消和无法判定为灰色。没有记录时不填充模拟方块。
7. 点击方块可分别查看本轮和历史结果，按模型、检测类型切换，每页 12 条。拖动“结果卡片大小”可调整一排的数量，单张可放大。
8. 糖果回答按安全 Markdown 展示；鹈鹕和自由创作提供 HTML 预览与源码切换。判定来源、具体分项证据、裁判模型、证据置信度和生成/裁判 Token 用量收纳到“详情”。置信度不是经验证的准确率。历史保存在本站数据库中。

三种模式均不再调用 Manxue。本站直接向绑定渠道的 `/v1/responses` 发送固定测试题，再使用裁判 Key 请求本站网关。生成和评分分别按正常规则计费；裁判能读取本次测试回答/HTML，不会收到既有用户对话或被测渠道凭据。裁判 Key 不会发送给被测外部渠道。两个 HTTP 客户端都禁止重定向及环境代理；外部生成请求使用监控已有的 DNS/IP 安全检查。计划只保存渠道引用，不在公开配置和结果接口返回密钥、内部凭据指纹或裁判 Key ID。

服务端可用 YAML 或同名环境变量设置（部署方式需要把变量实际传入应用进程）：

```yaml
model_quality:
  judge_key_name: 测试降智
  judge_model: gpt-6.1-sol # 或 gpt-6-luna
```

对应 `MODEL_QUALITY_JUDGE_KEY_NAME` 和 `MODEL_QUALITY_JUDGE_MODEL`。模型固定写入每次运行快照，不会在失败后自动换模型重试。裁判地址固定为当前应用端口的 `http://127.0.0.1:<server.port>/v1`，要求应用监听 loopback 或通配地址；不能用表单指定外部裁判 URL。Key 必须属于计划创建者，精确同名且唯一，并满足正常网关的 IP、分组、余额和订阅等校验。

这里绑定的是**渠道监控**中已有 URL 和 Key 的记录；**渠道管理**中的渠道用于定价和模型映射，本身没有连接凭据。旧版填写本站 URL 和 Key ID 的计划仍可运行，编辑时可改为绑定已有监控渠道。

## 模式和判定含义

固定测试题与评分规则在 `backend/internal/service/model_quality_prompts.go`，当前版本 `native-v1`。裁判使用 Responses 结构化 JSON 输出；本站再次验证结构及分项 ID 后计算判定，不直接采用模型自由文本中的“正常”结论。

| 模式 | 评分依据 | 特别注意 |
| --- | --- | --- |
| 糖果 `candy` | 最终答案、充分性证明、最小性证明 | 仅出现数字 21 不足以通过 |
| 鹈鹕 `pelican` | 鹈鹕形态、自行车结构、骑行连接、运动关系、完整性 | 分析坐标和变换；不按代码长度、JS 有无或配色判断 |
| 自由创作 `creative` | 主体、构图、运动、暂停/继续交互、完整性 | 风格自由，不因不像某个模板而判失败 |

三种模式均可自定义被测模型，支持表单中的 low/medium/high/xhigh/max/ultra，但具体强度和服务等级必须由目标渠道支持。艺术模式不再硬编码只允许 gpt-6-astra。艺术裁判分析的是 HTML 源码，**没有实际运行浏览器或查看动画截图**；运行时不确定性不得冒充已证实的缺陷。用户手动预览不等于裁判已看过画面。

每项评分 0/1/2 分，分别代表明确核心错误、部分满足或证据不足、充分满足。置信度至少 0.8 且有 0 分项时显示“疑似降智”；无 0 分项且总分至少 80% 时显示“正常”，糖果额外要求三项全为 2 分。其余显示“无法判定”。这些是保守的初始规则，尚未经人工标注集校准，不代表准确率。

任务 `succeeded` 仅表示生成和评分完成，不代表通过。API 错误、超时、结构不合法和残缺输出显示“检测异常”，不会当作降智。近 24 小时通过率沿用 `正常数 / 全部已结束检测数`，因此异常、取消和无法判定也在分母中；它不等于模型能力准确率。

历史 Manxue 判定不会被覆盖。原生版题目和裁判契约已变更，不能直接比较升级前后通过率。近 24 小时统计仍按配置聚合，切换期间可能混合两种来源，页面会提醒查看来源。

已有计划不能更换分组及已绑定的监控渠道；空闲时可修改模型组合，历史记录保留原快照。渠道 URL/Key 更新在后续执行时生效。生成后若渠道凭据已变化，本次评分停止。本站网关继续负责模型映射、账号选择及兜底；外部渠道遵循其自身路由，归属分组用于展示和权限。配置快照并不是最终命中账号的证据。裁判与被测渠道若共享上游，会产生相关故障及偏差风险，建议使用独立稳定的裁判线路。

## 执行与持久化

- MySQL 迁移 `104_model_quality_monitor.sql` 创建计划和运行记录表；根目录 `246_model_quality_monitor.sql` 保留 PostgreSQL 迁移镜像。当前应用初始化使用 MySQL。
- 原生升级复用现有 JSON 列保存版本、评分和内部裁判 Key ID，不需要新增 SQL 迁移。
- 数据库锁定计划行后创建一轮多组合记录；同一计划同时最多一轮未结束任务。运行中的计划不能修改。
- 两个后台工作线程按租约领取任务，分“生成”和“评分”两个持久化阶段。每阶段至多发起一次 HTTP 请求；生成完成后先保存作品，再领取评分阶段。
- 请求前写入 `submitting` 和长于请求超时的租约。重启遇到不确定的在途请求时标记异常，不自动重发。已保存生成作品且尚未提交评分时可继续评分。HTTP 错误也不由检测服务自动重试；网关自身的重试策略不受此变更影响。
- 生成超时 8 分钟、评分超时 2 分钟；首次实际执行后超过 12 分钟停止。每两秒检查取消及租约变化，取消时中断本地请求，但上游已经发生的用量仍可能计费。队列等待不冒充生成耗时。
- 升级前已提交到 Manxue 的未完成任务标记异常，不再查询或取消远端，也不会重新生成；远端可能继续运行及计费。旧的排队但未提交任务按新规则执行；已结束历史不变。
- 每次执行前重新读取渠道凭据，检查渠道启用状态及协议；若 Key 属于本站，核对实际分组、状态、过期与限额。旧版计划继续校验 Key 所有者。授权被移除、IP 限制、订阅或余额不足等仍由正常网关拒绝，不绕过现有校验。
- 使用当前请求持有的凭据脱敏返回正文、HTML 和评语，再写入数据库。裁判异常保留已生成的脱敏作品；只返回安全的 HTTP 状态，不回显上游错误正文或 URL。
- 只保存已知的结果字段并脱敏；不公开远端任务能力 ID。源码始终作为文本展示。页面预览保留 CSS、SVG 和内联绘图脚本，放入仅允许脚本、没有同源权限的 sandbox iframe；保留 SVG `<use>` 对当前文档图形的复用（`href="#id"`、`xlink:href="#id"`），避免车轮、云朵等图形丢失，同时移除两种属性中的外部引用。预览会测量完整 HTML（包括页脚）并等比缩放到卡片区域，隐藏 iframe 内外滚动条；不会把内容裁成只有上半部分。过滤外部脚本、嵌套页面、表单和跳转链接，并用独立 CSP 禁止网络请求。外部 CDN 依赖不会加载。内联脚本沿用当前页面 nonce 以兼容生产 CSP，不能读取本站登录态或 DOM。
- 记录目前持续保留，不自动删除。停用计划可停止后续定时检测，已有记录仍可查。

## API

管理端（已有管理员认证和审计中间件）：

- `GET /api/v1/admin/model-quality`：计划及最近 60 次、累计统计、关联的监控渠道 ID。
- `GET /api/v1/admin/model-quality/options`：分组和可绑定监控渠道的非敏感选项，不返回 URL 或 Key。
- `POST /api/v1/admin/model-quality`、`PUT /api/v1/admin/model-quality/:id`：新建、修改。
- `POST /api/v1/admin/model-quality/:id/run`：创建检测，HTTP 202。
- `GET /api/v1/admin/model-quality/:id/history?page=1`：每页 50 条历史摘要。
- `GET /api/v1/admin/model-quality/groups/:groupID/history?page=1`：同组各计划合并的历史摘要，每页 50 条。
- `GET /api/v1/admin/model-quality/groups/:groupID/results?benchmark=pelican&page=1`：按检测类型筛选后分页的完整卡片结果，每页 12 条；包含有权查看的类型列表和 `has_more`。网格一次请求一页，避免逐卡查询。
- `GET /api/v1/admin/model-quality/:id/results`：按 `batch_id` 或 `exclude_batch_id` 选择本轮或历史，支持 `model`、`benchmark`、`page` 筛选。
- `GET /api/v1/admin/model-quality/runs/:id`：完整结果。
- `POST /api/v1/admin/model-quality/runs/:id/cancel`：请求取消，HTTP 202。

用户端提供 `/api/v1/model-quality` 下对应的列表、历史和详情 GET 接口；无创建、修改、运行和取消权限。

## 验证范围

自动测试使用模拟 Responses 客户端/HTTP 服务与数据库桩，覆盖三种模式、JSON/SSE、重定向/SSRF、响应限制、评分结构、Key 所有权与同名歧义、渠道凭据继承与轮换、取消/租约失效、失败和重启不重复计费、历史兼容及前端证据安全显示。它们不证明真实裁判线路可用，也不证明判定准确。

2026-10-31 真实验证：使用指定的“测试降智”Key 调用 Luna 六次、6.1-sol 一次，均收到网关 HTTP 502；运维日志显示上游账号 4595 返回 403 `Upstream access forbidden`。未取得任何成功裁判评分，也未完成阈值校准。本地改动尚未部署。详细历史依据、反例与后续验收见 [原生检测历史分析](native-assessment-analysis.md)。
