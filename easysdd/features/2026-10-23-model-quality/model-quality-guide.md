# 分组降智检测（Manxue）

管理员配置入口：**渠道监控 → 降智检测**。管理员和用户都可从对应渠道的**降智状态**方块打开结果。

## 配置和使用

1. 在渠道监控中配置并启用要检测的 OpenAI 渠道。该渠道须有有效 Key、公网 HTTPS 地址且支持 Responses 接口。
2. 新建检测计划，选择**绑定渠道**，无需重复填写 URL 或 Key。使用本站 Key 时自动识别并锁定实际分组；外部渠道 Key 则选择结果归属的分组。每次检测读取渠道最新的 URL 和 Key，地址按渠道监控约定补齐 `/v1`。
3. 选择模式、请求模型、思考强度和服务等级。保存默认不启用定时检测；点击“立即检测”可手动执行。定时间隔范围为 15 分钟至 7 天。
4. 需要用户看到结果时，开启“向有权限使用此分组的用户展示”。普通用户的列表、历史和详情都会校验分组权限。
5. 渠道卡片的可用性方块下方只显示一条合并后的**降智状态**，把该组可见计划（糖果、鹈鹕等）的最近 60 次真实记录按左旧右新排列：绿色为正常，黄色为疑似降智，检测异常、取消和无法判定为灰色。没有记录时不填充模拟方块；点击任意方块后，在详情中用检测类型 Tab 分开查看。
6. 点击某个方块，弹窗以卡片网格展示当前分组的检测历史，按糖果、鹈鹕、自由创作 Tab 切换。每个类型独立分页，每页 12 条；点击的旧记录会在首页保留并标记。运行中的卡片显示加载动画，结束后自动更新结果。拖动“结果卡片大小”可调整一排的数量，单张可放大。
7. 糖果回答按安全 Markdown 展示；鹈鹕和自由创作提供 HTML 页面预览与原始源码切换。页面按固定画布等比缩放，避免小卡片只显示页面一角。耗时和时间常驻，判定原因与 Token 用量收纳到卡片“详情”。历史保存在本站数据库中，不依赖 Manxue 的一小时保留期。

Manxue 会收到所绑定渠道的 Key 并调用该渠道地址，真实检测按渠道正常规则计费。只会发送专用检测请求，不会上传既有用户对话。服务器固定向 `https://manxue.ai/api/v1/tests` 提交任务，不跟随重定向。检测计划仅保存渠道引用，配置及结果接口均不会返回 Key 文本或远端任务 ID。

这里绑定的是**渠道监控**中已有 URL 和 Key 的记录；**渠道管理**中的渠道用于定价和模型映射，本身没有连接凭据。旧版填写本站 URL 和 Key ID 的计划仍可运行，编辑时可改为绑定已有监控渠道。

## 模式和判定含义

接口契约来自 [Manxue 官方 API 文档](https://manxue.ai/api)，核对日期：2026-10-23。

| 模式 | 限制 | 本站显示 |
| --- | --- | --- |
| 糖果 `candy` | 可自定义模型；low/medium/high/xhigh/max/ultra | passed → 正常/通过；incorrect → 疑似降智/未通过；error → 检测异常 |
| 鹈鹕 `pelican` | 当前文档要求显式指定 gpt-6-astra；low/medium/high | normal → 正常；degraded/suspicious → 疑似降智；其他 → 无法判定 |
| 自由创作 `creative` | 同鹈鹕模式 | 同鹈鹕模式 |

三种生成模式均使用 Responses 协议，目标分组必须支持。纯 HTML 分类不调用分组，不属于分组实测，所以不提供为定时检测模式。

任务 `succeeded` 仅表示任务执行结束，不代表答题通过。通过率为 `通过数 / (通过数 + 未通过数)`，检测异常、超时、取消、无法判定和正在执行的任务不进入分母。单次结果不能证明模型身份或整体能力。

同一计划的绑定渠道、分组、模型、模式、请求思考强度和服务等级固定，避免修改后混合样本；更换这些维度请新建计划。渠道内更新 URL 或 Key 会在下一次检测时生效。每次运行记录发起时的分组及渠道配置；当渠道地址指向本站时，正常网关继续负责模型映射、账号选择、重试及兜底。外部渠道则直接按其自身路由执行，归属分组用于展示和权限。Manxue 不返回本站最终账号或兜底渠道，所以不能将配置快照当成最终命中证据。

## 执行与持久化

- MySQL 迁移 `104_model_quality_monitor.sql` 创建计划和运行记录表；根目录 `246_model_quality_monitor.sql` 保留 PostgreSQL 迁移镜像。当前应用初始化使用 MySQL。
- 数据库锁定计划行后创建本地运行记录；同一计划同时最多一条未结束记录。运行中的计划不能修改，避免凭据或检测参数变化。
- 两个后台工作线程按数据库租约领取任务，每次只执行一个提交/查询/取消步骤。已取得远端 ID 的记录可在重启后继续 GET 查询，约每 4 秒轮询。
- 提交使用本地记录 ID 作为幂等键。429/503 按 Retry-After 和带抖动的退避处理。网络中断等使提交结果不确定时记录异常，停止自动重发，避免远端任务或幂等记录因重启丢失造成重复扣费。
- 查询 404 标为任务过期/丢失，不重新 POST。运行最长在本站占用 12 分钟，到期记录超时并尝试取消；远端文档给出的任务上限为 10 分钟。
- 每次执行前重新读取渠道凭据，检查渠道启用状态及协议；若 Key 属于本站，核对实际分组、状态、过期与限额。旧版计划继续校验 Key 所有者。授权被移除、IP 限制、订阅或余额不足等仍由正常网关拒绝，不绕过现有校验。
- 提交时在内部记录凭据指纹；任务结束时若凭据已轮换或不可读，不保存远端自由文本，以免回显旧 Key。指纹不会出现在公开 API 中。
- 只保存已知的结果字段并脱敏；不公开远端任务能力 ID。源码始终作为文本展示。页面预览保留 CSS、SVG 和内联绘图脚本，放入仅允许脚本、没有同源权限的 sandbox iframe；保留 SVG `<use>` 对当前文档图形的复用（`href="#id"`、`xlink:href="#id"`），避免车轮、云朵等图形丢失，同时移除两种属性中的外部引用。预览会测量完整 HTML（包括页脚）并等比缩放到卡片区域，隐藏 iframe 内外滚动条；不会把内容裁成只有上半部分。过滤外部脚本、嵌套页面、表单和跳转链接，并用独立 CSP 禁止网络请求。外部 CDN 依赖不会加载。内联脚本沿用当前页面 nonce 以兼容生产 CSP，不能读取本站登录态或 DOM。
- 记录目前持续保留，不自动删除。停用计划可停止后续定时检测，已有记录仍可查。

## API

管理端（已有管理员认证和审计中间件）：

- `GET /api/v1/admin/model-quality`：计划及最近 60 次、累计统计、关联的监控渠道 ID。
- `GET /api/v1/admin/model-quality/options`：分组和可绑定监控渠道的非敏感选项，不返回 URL 或 Key。
- `POST /api/v1/admin/model-quality`、`PUT /api/v1/admin/model-quality/:id`：新建、修改。
- `POST /api/v1/admin/model-quality/:id/run`：创建检测，HTTP 202。
- `GET /api/v1/admin/model-quality/:id/history?page=1`：每页 50 条历史摘要。
- `GET /api/v1/admin/model-quality/groups/:groupID/history?page=1`：同组各计划合并的历史摘要，每页 50 条。
- `GET /api/v1/admin/model-quality/groups/:groupID/results?benchmark=pelican&page=1`：按检测类型筛选后分页的完整卡片结果，每页 12 条；包含有权查看的类型列表和 `has_more`。网格一次请求一页，避免逐卡查询。
- `GET /api/v1/admin/model-quality/runs/:id`：完整结果。
- `POST /api/v1/admin/model-quality/runs/:id/cancel`：请求取消，HTTP 202。

用户端提供 `/api/v1/model-quality` 下对应的列表、历史和详情 GET 接口；无创建、修改、运行和取消权限。

## 验证范围

自动测试覆盖接口契约、重定向与响应大小限制、判定映射、组/Key 权限、渠道凭据继承与轮换、分组结果按类型分页、失败不自动重复提交、重启继续查询、取消、数据库租约及排他排队。前端测试覆盖渠道卡片关联、绿黄方块、Tab 切换时忽略旧响应、异步结果更新、翻页和表单仅提交渠道引用。浏览器已验证桌面/手机/暗色布局、卡片缩放、源码切换、单张放大，以及带 nonce CSP 下的 SVG 和脚本动画、阻止预览访问父页面和发起 fetch。测试使用模拟 Manxue 接口与临时页面，不消耗真实模型额度或写入真实数据库。真实渠道到 Manxue 的端到端检测尚需使用有效渠道执行验证。
