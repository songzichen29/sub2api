## 建议的判断依据

鹈鹕检测需要回答五个具体问题：鸟是否可辨识且身体连续；自行车是否结构完整；座位/车把/脚踏是否与骑手接上；转过四分之一圈和半圈后关系是否仍成立；作品是否完整自包含。典型可核对证据是轮轴坐标、CSS `transform-origin`、父子坐标系、CSS transform 对 SVG translate 的覆盖、两脚相位及腿脚接点。

不把标题、配色、代码长度、Token、响应时间、框架、JS 有无作为判据；也不把“作品丑”直接等同于“模型降智”。一次任务失败只能说明该样本表现有问题，不能证明模型被换掉或整体能力下降。确认趋势应结合同规则重复样本及人工复核。

## 已实现的原生方案

糖果、鹈鹕、自由创作在本地新版中全部移除旧外部测试服务调用。渠道自己生成，默认由 `gpt-6.1-sol` 分析，不自动切换到其他模型。裁判 Key 按计划创建者和精确名称“测试降智”查找；同名多个会报错，不随意挑选。线上旧版尚未替换，不能让新旧后台同时消费共享队列。

糖果核对最终答案 21 和充分性/最小性证明。题目数量为圆形苹果7、桃子9、西瓜8，星形苹果7、桃子6、西瓜4。9圆+12星能保证成功；20不能保证。只在回答里出现数字21不算正确。

艺术模式裁判只读 HTML 源码，**未运行浏览器、未看到截图**。现阶段不属于视觉自动化验收；复杂运行时关系无法可靠判断时应降为“无法判定”。作品被作为不可信数据，系统指令要求忽略作品中的评分命令和自我声明，但提示词防注入不能保证裁判绝不会被误导。

固定题目、rubric、结构和阈值版本为 `native-v1`；题目约束与旧系统并非完全相同，旧标签不会重新写成新判定，也不能据此计算新裁判准确率。详情保存每项0/1/2分及证据；置信度≥0.8且存在0分判疑似，无0分且总分≥80%判正常（糖果要求全项2分），其他无法判定。**0.8/80%是尚待校准的初始阈值，不是测得的准确率。**

接口失败、输出不完整或评分结构不合法都归检测异常。裁判失败保留作品。每阶段只主动发送一次请求，不确定结果不自动重发，防止重复计费。网关可能按自身策略重试/兜底。新旧规则切换时，既有近24小时聚合可能混合两者，页面给出来源与提醒；不把这一统计当作同一测量尺度下的升级对比。

## 上线前验收

1. 恢复“测试降智”Key 的裁判线路，或明确指定另一条可用 Key；优先独立于被测线路，减少共同故障和偏差。
2. 先验证一条裁判请求能完成，再用少量隔离样本验证生成→评分→持久化链路，不批量补跑历史。
3. 人工按五项标准标注一组历史作品，覆盖长代码失败、无JS正常、静态结构正常但动态漂移、部分遮挡等反例；不要直接采用旧标签作为答案。
4. 进行重复评分，检查一致性、误报和漏报，再调整置信度/评分规则；对复杂运动结合浏览器多帧人工复核。任何规则变化增加版本。
5. 获得部署授权后按生产分支流程上线，先手动跑一轮，检查错误、费用和耗时，再启用定时任务。
