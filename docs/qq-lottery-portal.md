# 站内转盘抽奖与加群引导

用户入口为 `/lottery`（需要登录），菜单、个人中心、充值页、充值结果页和卡密兑换页提供入口。页面包含本期充值本金、累计获得/已用/剩余次数、下一档差额、保底进度、公开奖池和本人本期抽奖记录。时间统一显示为北京时间。

## 业务边界

- 未绑定 QQ、未入群的用户也可以查看属于本站账号的次数。
- 与 QQ 指令复用 `lotteryState` 和现有统计起点；次数查询不重发次数、不改写既有余额与抽奖账本。退款、充值赠送排除、成长奖励次数及保底计算沿用现有规则。
- 充值赠送次数按订单实际支付的人民币本金（CNY）计算，不按到账 USD 额度或当前充值倍率倒推。使用订单保存的 `pay_amount` 和 `fee_rate` 剔除向上取整到分的手续费，优惠券及折扣减免不计入。部分退款按订单退款比例扣减；退款中暂停计入。仅计人民币支付，历史支付宝、微信及易支付订单可由提供方确定人民币币种，其他缺失币种的订单不推定人民币。
- 余额兑换码无法证明人民币实付，不计充值赠送次数；任务发放的独立次数保留。口径修正会实时减少尚未使用的多送次数，已抽次数照常扣除、已发奖不追回、不改旧抽奖快照；新抽奖快照标记 `recharge_currency=CNY`。签到及成长任务的 USD 充值资格口径不随本修复改变。
- 管理员可生成 `lottery_chances` 类型兑换码，`value` 为每码赠送次数（1～1000 的整数），支持批量、到期时间及现有停用功能。用户从原兑换入口领取，单码只可使用一次；标记使用与写入 `qqc_lottery_chance_grants` 在同一事务内完成，以 `redeem-code:<id>` 唯一来源防重。按实际兑换时间纳入当前期，和任务赠送次数一样计入额外机会、扣除已抽次数；不增加余额、人民币充值本金或任何充值返利。删除已用码不会撤销已发放次数。
- 网站提供直接转盘抽奖，登录账号有剩余次数即可参与，无需绑定 QQ 或加入群。网站以抽奖活动开关为准，不依赖机器人在线或机器人总开关。QQ 群入口仍校验开放群、活动开关和账号绑定。
- 两种入口调用同一结算函数、次数计算和保底规则；站内请求使用登录身份，奖项由服务端安全随机选择。站内记录使用 `website` 来源，管理员活动记录同时包含网站记录。
- `request_id` 按登录账号隔离，重复提交返回原结果。前端按用户保存待确认请求，超时、刷新或离开页面后可查询同一结果，不重新扣次。事务共享 QQ 的用户锁和 MySQL 事务锁，失败整体回滚；正奖励写入余额、奖励账本和管理员余额记录，零奖励仍消耗一次。
- 转盘扇区等分，仅展示抽奖过程，不代表概率。使用服务端返回的实际奖池和索引定位中奖扇区，兼容配置变更与保底奖池。完整概率及规则可展开查看。
- `PAID` / `RECHARGING` 且尚未完成的余额充值展示“同步中”；只有现有充值结算完成后才反映到次数。页面每 5 秒刷新，最多 12 次，之后提示手动刷新，离开页面停止轮询。
- 抽奖页面绑定后自动刷新，回到浏览器也刷新；复制“抽奖”指令不会代替用户发送 QQ 消息。

## 管理配置

在 QQ 机器人活动 → 抽奖配置中设置 `public_groups`，字段为 `group_id`、`name`、`join_url`。数组顺序就是展示顺序。使用原抽奖配置的 ETag/If-Match 保存，不需要数据库迁移。

只允许配置已开放且未关闭活动的群，最多 20 个，群号不能重复。允许 QQ 官方 `https://qun.qq.com`、`https://qm.qq.com` 加群链接，也可留空仅显示群号。二维码在浏览器中从链接生成，不请求第三方二维码服务。群后来被停用时，用户接口立即过滤该群。

默认公开群列表为空，不自动公开全部机器人群。部署后管理员须选择希望展示的活动群；未配置时，页面提示联系管理员。

## 用户接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/user/qqbot/lottery` | 本人次数、规则、绑定 QQ、公开群、是否有充值结算中 |
| `GET /api/v1/user/qqbot/lottery/draws?page=1&page_size=20` | 本人本期抽奖记录（最多每页 100 条） |
| `POST /api/v1/user/qqbot/lottery/spin` | 扣除一次机会并抽奖；JSON 仅需 `request_id`（16–64 位字母、数字或连字符），重复 ID 返回原结果 |
| `POST /api/v1/user/qqbot/lottery/membership` | 根据登录账号当前绑定的 QQ 核验入群状态 |

所有接口使用登录身份，忽略客户端传入的用户/QQ 身份；不返回其他成员、邮箱或完整机器人配置。响应禁止缓存。群成员探测在数据库事务外进行，整体最长 8 秒、最多 4 个并发，并沿用站点重查询限流。

核验返回 `unbound`、`member`、`not_member`、`unknown` 或 `disabled`。单成员查询失败不能证明不在群；需成功查询完整成员列表且确认机器人身份后才能判定不存在。网络失败、空/异常响应均返回 `unknown`。已有绑定、历史入群记录不作为当前在群证明；探测期间发生绑定变化或新的入退群事件会使结果失效，需再次刷新。

## 本地验证范围

后端测试覆盖未绑定账号的次数、公开群过滤、本人记录隔离、双数据库分页绑定、链接校验及入群核验三态。前端测试覆盖未绑定/绑定后状态、核验失败、关闭活动时保留记录、充值结算轮询与销毁清理。实际 NapCat 成员接口和 QQ 抽奖回执仍需部署后验收，本地测试不代表已在线启用。
