# QQ 群机器人（完整社区模块）

参考 DeanZFC/sub2api-custom 的 QQ 业务模块，保留普通 QQ + NapCat / OneBot v11 接入。来源、基准提交和许可证见 [来源记录](qq-community-upstream.md)。

## 管理入口

后台「QQ 机器人」包括概览、群配置、机器人配置、活动、绑定和记录；旧 `/admin/qq-bot` 自动跳转 `/admin/qqbot/overview`。原管理配置写接口返回 410，防止旧页面写入已经迁出的配置。

| 模块 | 功能 | 升级默认 |
| --- | --- | --- |
| 模型 | 按聊天 / 生图连接获取 Key 下全部模型，也可手填；支持 Chat Completions / Responses | 保留原聊天连接和模型 |
| 图片 | 文生图、图生图、引用群内原图或机器人近期图片、聊天工具生成图片 | 关闭 |
| 账号 | 网站绑定码双向确认、邮箱确认绑定、本人余额 / 今日用量 / 奖励查询、管理员解绑 | 保留原绑定 |
| 签到 | 随机金额、充值门槛、连续签到奖励 | 保留原签到金额；新增奖励关闭 |
| 活动 | 邀请奖励、抽奖及保底、成长任务、周期任务、排行榜及奖励 | 关闭 |
| 转账 | 手续费与限额、邮箱链接预览及确认、单次确认、记录 | 关闭 |
| 内容 | 自定义指令、站点知识、只读站点查询、试问、群历史、自主接话 | 自动接话关闭 |
| 运营 | 价格和健康通知、静默时段、群策略、群管理员、成员目录、防刷屏、诊断、持久队列与记录 | 通知及群管关闭 |

上游已退休的垃圾信息举报开关保持关闭。官方 QQ 的按钮菜单由群内指令替代。

## NapCat 配置

- 机器人 QQ：后台字段 `app_id`；OneBot Token：后台字段 `app_secret`（沿用参考接口字段名）。
- 连接：`wss://站点域名/api/v1/qq-bot/onebot/ws`，反向 WebSocket、Universal、array 消息格式。
- 使用 `Authorization: Bearer <Token>`、`X-Self-ID: <机器人QQ>`、`X-Client-Role: Universal`。
- 同机容器可使用 `ws://sub2api:8080/api/v1/qq-bot/onebot/ws`。Nginx 需转发 Upgrade / Connection，并设置足够的读超时。
- 单实例接受一条连接。配置关闭或凭据改变后旧连接关闭，由 NapCat 重连。概览和诊断显示连接状态。
- 群管理员功能要求机器人在 QQ 群具有相应权限。群管理操作必须收到 OneBot 成功回执才标记成功；发送不明结果不会自动重发。

## 模型与图片

聊天与生图各有「获取 Key 模型列表」，后端用对应 Key 请求 `/models`，返回全部非空、去重排序后的 ID。界面不会读取已保存 Key 明文；更换地址需要重新填写或显式清除对应 Key，避免转发原凭据。

生图地址留空时复用聊天地址；生图 Key 留空时可复用聊天 Key。启用生图前应确认所选模型支持 `/images/generations`；图生图还需支持 `/images/edits`。模型列表不等于上游一定支持所有协议。后台「测试连接」会实际调用模型并计费。

群内支持 `/帮助`、`/余额`、`/签到`、`/渠道`、`/聊天 问题`、`@机器人 问题`、`/生图 描述`（`/画图` 别名）、`/清空`（`/清空对话` 别名）。其余活动与查询以 `/帮助` 和后台真实功能清单为准。自然语言工具只提供已授权的只读站点查询及模型图片能力。

模型费用使用站点专用 Key，由站点承担。群上下文按群保存并带发言人身份，可能包含其他成员的近期普通发言；余额、绑定码等私密指令不进入共享上下文。`/清空` 只删除本人在当前群的历史。

## 资金和升级

- MySQL 迁移 `107_qq_community_full.sql`；PostgreSQL 迁移 `249_qq_community_full.sql`。37 张业务 `qqc_` 表，与原 `qq_bot_*` 表隔离；MySQL 另含专用锁表，共 38 张。
- 启动时在单事务中迁入原配置、绑定、待绑定码、签到账本和指令审计。配置与密钥保留加密存储；历史奖励只复制收据，不再次修改余额。旧历史任务永不重放。
- 新配置行作为迁移标记，重启不会重复迁入。旧表保留；原成员聊天历史不迁入群共享历史。
- 签到按北京时间和网站账号唯一约束；跨群、换 QQ、重复事件不能重复领取。余额、奖励和余额历史同事务提交，提交后清除鉴权及余额缓存。
- 转账只有邮件确认后才扣款；单次 token、锁定收付款账号、余额与历史同事务；未确认申请不扣款。
- MySQL 写事务以既有专用锁行替代 PostgreSQL 事务 advisory lock。模型和 QQ 网络调用在资金事务之外；后台通知读取站内数据时持有事务锁。
- QQ 管理配置、模型探测和试问的请求正文不进入审计，避免记录 Key；GET 配置仅返回凭据是否存在。
