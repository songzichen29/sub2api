# QQ 业务页面回复

## 指令

- `监控` / `渠道状态`：按站点当前监控模式查询。主动监控复用 `/monitor` 的监控卡片、历史状态条和绑定用户可见的降智状态。
- `余额`：展示本人绑定账号的钱包余额，复用 `/key-usage` 的余额圆环；不代表某个 API Key 的限额或订阅额度。
- `用量`：仅展示今日（北京时间）按模型汇总的请求、输入输出、缓存 Token 和实际费用。复用 Key 查询页的模型表格。
- `价格 模型名 [分组关键词]`：一个页面展示所有匹配报价。可在网页继续筛选，不再逐个分组、逐页投递。

群内发送真实 Vue 页面的浏览器截图和对应页面链接。网页保留筛选、状态条提示和站点跳转；截图是查询时刻的静态快照。帮助、签到、活动规则等简单回复继续使用原有卡片。截图失败时返回完整页面链接；只有 QQ 明确拒收时才尝试文字回退，投递超时不重发。

## 登录和隐私

查询身份来自 QQ 绑定记录，模型和页面参数不能指定其他账号。报告使用 256 位随机能力令牌，令牌放在 URL fragment，只通过请求体提交；不使用用户登录会话或 API Key。链接有效 10 分钟，机器人重启后失效；停用机器人、移除允许群、解绑或换绑后拒绝读取旧报告。

链接和群内图片都可被收件人查看。页面明确说明链接的可见性。报告不包含 API Key、上游配额、管理员配置、生成源码或原始错误信息。每个进程最多保留 64 份报告，每份最大 2 MiB。

## 截图运行

生产镜像安装 Chromium 和中文字体。截图仅导航固定的应用 loopback 地址，每次创建独立浏览器，不加载用户或管理员 Cookie。并发限制为 1，包含排队的超时为 35 秒；等待数据、字体和布局完成后截图。页面过长或图片过大时发送完整页面链接，不截断、不自动分页。

管理员可用 `POST /api/v1/admin/qqbot/page-preview` 预览真实页面，参数为 `kind`（monitor/balance/usage/prices）、`group_id`、`member_id`，价格附 `model` 和可选 `filter`。加 `?image=1` 返回真实浏览器截图。这些接口受管理员认证和重接口限流保护，不向 QQ 发消息，不调用模型，不发奖。

## 其他修复

抽奖规则和次数查询使用只读事务，不申请用户写锁；真正抽奖保留原事务锁。次数回复包括累计抽奖、正额度中奖和剩余次数。生图完成文字和图片合并投递，消除重复完成提示。兼容渠道忽略 required 工具要求时的普通文字回复；只有明确的图片工具和独立审核可触发生图。

机器人未配置外网/X 检索工具。查询最新推文时明确告知不能核实，不反复报生成失败或假装联网。

QQ 排行榜入口、帮助、配置路由、自动结算启动和排队通知已停用；历史资金与奖励记录保留。
