# QQBot 独立运行环境

链路：NapCat → OneBot 分流 → AstrBot → DSH SDK → 已授权模型 API。签到、余额、绑定、转账、抽奖、图片业务及通知仍由原 Sub2API 执行；分流器保留原 OneBot 反向连接和 API 回执。

## 发布与部署

生产分支的 `Build QQBot Runtime` 构建独立 `qqbot-runtime` 镜像。等待构建成功，核对 OCI revision 后按摘要部署。`compose.example.yaml` 是部署模板；真实令牌只在服务器受保护文件里维护。模型、人格、群权限和接话策略统一由站点后台维护，不提交到 Git。

复制本次提交的 `astrbot_plugin` 到模板指定的 `source/astrbot_plugin`，只读挂载。服务状态、配置和会话分别持久化，更新镜像不能删除数据目录。保留上一个镜像摘要、NapCat 配置及当前 Compose 以便回滚。不要运行 `docker compose down -v`。

桥通过 HTTPS `/api/v1/qq-bot/runtime/config` 获取后台已保存配置，Bearer 使用原 OneBot token，并校验 X-Self-ID。每 10 秒拉取并上报状态；45 秒未成功同步时拒绝新聊天。密钥不出现在 `/policy`、`/health` 或公开管理配置中。DSH 子进程只得到模型密钥及必要启动变量，QQ 专用 profile 没有命令、文件、插件管理和子 Agent 工具。模型或人格变化会换会话并保留公开聊天记忆。

`config/config.json` 只保留部署信息，例如：

```json
{
  "bot_id": "1849138657",
  "site_config_url": "https://api.dwai.cloud/api/v1/qq-bot/runtime/config",
  "business_ws_url": "wss://api.dwai.cloud/api/v1/qq-bot/onebot/ws"
}
```

启用前在站点保存 `runtime_chat.enabled=true` 并迁移当前有效模型、协议、Key、人格、白名单和额度。保存后旧 `autonomous`、`history_messages`、`meme_enabled` 不再持久化或公开，旧聊天任务和旧模型测试入口停止执行。升级旧配置时不可把旧聊天型号误当成当前 DSH 的可用型号。

后台 `chat_protocol=responses` 对应 DSH `openai-responses`，`chat_completions` 对应 `openai-completions`。模型列表可见不代表视觉能力可用，须通过目标模型请求核验。模型上下文容量填写真实支持的 tokens 数，默认 65536；它不是聊天记录条数上限。

群内完整的本人余额、今日用量、抽奖次数查询不需要 @ 或斜杠，例如“查下我的余额”“我让你查下我的余额”。由站点按消息发送者的绑定查询，保留原文，不调用聊天模型。一般讨论（如“余额是什么”）、他人账户、否定句及混合转账请求不自动变成账户查询。查询语法需与后端 `natural_account.go` 保持一致。

先部署支持 `sub2api_observe_only` 的 Sub2API，再启用 `business_observation: true`。开启后白名单群的聊天及仅 @ 其他人的消息也送给原站点，保留防刷、群记录和图片引用；观察消息不创建聊天或业务任务。业务指令仅执行一次。旧版站点未支持此标记时禁止开启。

## 会话和投递

同一个群的公开聊天按机器人和群共享，记录 QQ、昵称与时间，能结合多人的发言；不同群和私聊相互隔离。SQLite 和 raw JSONL 持续保存原文，没有固定条数或年龄截断。达到模型容量预算时，先成功保存摘要再推进游标，后续通过摘要和同群原文检索继续会话。完整原文不可能同时塞入有限的模型上下文。业务查询、绑定、密码及模型密钥不进入公共聊天记忆；助手回复只有确认送达才进入公共历史。

升级会导入旧分成员的群记忆；私聊不会导入群，未确认送达的助手回复不导入。`/清空` 重置该群活动上下文和检索（只允许本站配置的该机器人/该群管理员或当前 QQ 群管理员），私聊自行重置；审计原文和明确收藏保留。群管理员不会因此获得其他群的清空权限。DSH 会话只有收到完整 QQ 发送回执后才成为下一轮可恢复的会话；被限额、取消、部分发送或未确认的回答不进入模型会话记忆。旧回合的迟到回执不会覆盖新回合会话。

欢迎由站点处理已开放群的真实入群事件：提及新成员、支持 `{name}` / `{qq}` / `{group}`，不调用模型。重复、超过 10 分钟、机器人自身和关闭通知的群不发欢迎，发送未确认不重试。不自动接入新群，也不扩大白名单。

同群按顺序处理；不同群/私聊最多四个独立 DSH 进程并发，每个进程使用独立目录和绑定当前会话的工具令牌。同会话在 AstrBot 最多32条等待/处理中消息，桥最多64条等待消息。225秒期限包含下载、排队和模型处理；客户端取消或排队过期后不再启动模型。重复消息复用已完成结果，中断与失败不自动重跑。模型达到输出上限但已返回文字时保留文字并标明未完整；摘要不接受截断结果。

AstrBot 在发送前持久领取投递标记，并重新核对当前群、聊天和图片发送权限。回复首段引用原消息；每段独立保存 QQ 回执，只有所有段成功才记为送达，部分成功或中断保留已有回执且不自动重发。准备好图片但没有最终文字仍可发送。分流器不重放 QQ API 动作。上游暂时不可用时分流器记录计数并丢弃当时事件，不自动补执行资金操作；必须查看健康接口和实际消息记录。

全套健康检查包括桥 8787、AstrBot 6185、分流器 6200、原 Sub2API OneBot 连接，以及用户在允许群发出的一次真实聊天/站点指令。端口可访问或协议探测通过不代表 QQ 已完成双向收发验收。运维测试不得主动给真实群发消息。

## 运行边界

### 指定时点热群与北京时间

后台“群聊、记忆与欢迎 → 指定时点热群”设置 `runtime_chat.proactive_enabled`、`proactive_groups`、`proactive_times` 和 `proactive_idle_minutes`。时间点按北京时间 HH:MM 填写，不需要填写 cron；默认提供 12:00、14:00、18:00、21:00，开关默认关闭且不自动选择新群。热群与普通接话开关独立，群权限、全局/群额度和群接话额度继续约束热群，不使用最后说话成员的身份或个人额度，也不执行账户与图片工具。

到点由 DSH 结合本群共享上下文和时段生成简短话题。指定安静时长内有群成员发言则跳过；生成期间有新发言、群被禁用或配置关闭，投递前取消。时点按机器人/群/北京时间日期去重持久化，生成或投递不明不重试；重启不补发早于启动分钟的时点，生成超过五分钟也不发送。AstrBot 每 15 秒检查，可在没有新消息或重启后工作；QQ 发送必须保存实际消息回执。忙碌、模型跳过、生成、取消和投递结果通过结构化日志及 `proactive_slots` 记录。

模型当前时间、群历史、检索原文和摘要输入统一为 `Asia/Shanghai`、带 `+08:00` 的时间。审计原始数据仍按 UTC 保存。系统时间规则明确普通口述时间默认北京时间，不因底层 UTC/Z 时间戳再次加八小时；新规则会更新 DSH 会话身份，保留原始记忆。

管理端口默认只监听服务器本机，需通过已有受保护管理通道访问。定时主动开口默认关闭；普通群聊自主接话继承已确认配置。陌生人私聊只交给原绑定流程。模型费用走配置的 API 凭据。桥使用持久化计数器限制成员、群和全局每日调用、自主接话每日调用及每小时/每日回复；接管当天可导入原站点计数作初始额度。这些计数不回写原站点聊天统计，站点 API Key 自身的费用/额度约束继续生效。

DSH 注册六个受限工具：`generate_image`、`edit_image`、`web_search`、`web_fetch`、`send_meme`、`collect_meme`。不提供命令、文件或管理工具。自然语言画图和原图编辑经认证 `/runtime/tools` 进入原站点任务队列，以原 QQ 消息 ID 去重，沿用生图配置、额度和真实发送回执。编辑携带经过格式/大小校验的原图，使用 images/edits；原图缺失或编辑失败不回退为文生图。工具的 queued 仅表示受理，不表示出图。升级先发布站点后端，再更新桥镜像和 AstrBot 挂载的插件目录。

联网查询通过站点访问公开来源，返回来源 URL 与检索时间；网页不携带站点凭据，DNS 和各次重定向均校验公网地址。来源失败必须如实说明。后台 `runtime_chat.web_enabled`、`memes_enabled`、`collect_memes` 独立控制能力，不恢复旧自主接话设置。

表情包先匹配本会话收藏和24小时搜索缓存，再访问现有公共搜索来源；搜索及换词回退合计最多60秒。公共来源仍可能不可用，随机请求可使用本会话收藏兜底，精确关键词不擅自替换成不相关图片。搜索结果缓存与人工收藏分开，自动再次收集不会覆盖人工标签。

收藏/编辑优先当前消息原图，再明确引用；都没有时仅允许当前发送者最近10分钟的图片。当前图或引用下载失败绝不换用其他成员的图。每次最多4张、单张6MiB、合计12MiB，保留原消息编号，超过限制需分批发送。关闭看图只禁止向模型转发图像，明确收藏普通照片和原图编辑仍可下载工具附件；模型不能声称看过这些工具附件。引用携带原消息ID、作者和文字；私聊只读取同一对话的消息，机器人发出的私聊引用必须有该会话的发送回执。GIF原始字节保留，不声称视觉模型理解了完整动画。

临时原图和搜索缓存分别保留24小时且各不超过128MiB；终态发图资产最多7天，发送资产总量上限256MiB，容量回收只移除终态资产，未决发送不被挤出。收藏上限1GiB，满后停止添加而不自动删除用户收藏。运行诊断保留30天；原始聊天审计保存策略不变。

后台概览、聊天配置和“运行记录 → 聊天记录”展示桥上报的调用、确认送达、失败、未确认、排队和运行数，以及最近20条状态/原因。45秒未同步或跨北京时间日期后指标标为未知，不显示为零；业务任务仍有独立记录。日志和状态上报不包含聊天正文、原图、模型答案或凭据。
