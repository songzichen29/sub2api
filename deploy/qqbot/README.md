# QQBot 独立运行环境

链路：NapCat → OneBot 分流 → AstrBot → DSH SDK → 已授权模型 API。签到、余额、绑定、转账、抽奖、图片业务及通知仍由原 Sub2API 执行；分流器保留原 OneBot 反向连接和 API 回执。

## 发布与部署

生产分支的 `Build QQBot Runtime` 构建独立 `qqbot-runtime` 镜像。等待构建成功，核对 OCI revision 后按摘要部署。`compose.example.yaml` 是部署模板；真实令牌、模型连接和 QQ 配置只在目标服务器的受保护文件里维护，不提交到 Git。不要用替换源码的方式修复已发布容器。

复制本次提交的 `astrbot_plugin` 到模板指定的 `source/astrbot_plugin`，只读挂载。服务状态、配置和会话分别持久化，更新镜像不能删除数据目录。保留上一个镜像摘要、NapCat 配置及当前 Compose 以便回滚。不要运行 `docker compose down -v`。

模型密钥挂载到 `/run/secrets/model-api-key`；DSH 子进程只得到模型密钥及必要启动变量。QQ 专用 profile 使用同版本 SDK、持久化会话，没有命令、文件、插件管理和子 Agent 工具。模型地址和型号由 `config/config.json` 提供，白名单按机器人、群和私聊身份检查。模型列表可见不代表视觉能力可用，必须单独验证图片输入。

## 会话和投递

群会话按机器人、群、发言人隔离；私聊按机器人和用户隔离。人格共用 `config/SOUL.md`，raw 记忆分文件追加。记忆是同一 scope 的历史检索，不自动将聊天原话改写成可信人格规则。`/清空` 清理当前发言人的活动会话及检索记忆，审计原文仍保留在 raw 文件和 DSH 历史中，不能当作彻底删除数据。

单个 DSH 进程串行运行，重复消息复用已完成结果；中断与失败不会自动重跑。AstrBot 在发送前持久领取投递标记，投递结果不明时不重复发送。分流器不重放 QQ API 动作。上游暂时不可用时分流器记录计数并丢弃当时事件，不自动补执行资金操作；必须查看健康接口和实际消息记录。

全套健康检查包括桥 8787、AstrBot 6185、分流器 6200、原 Sub2API OneBot 连接，以及用户在允许群发出的一次真实聊天/站点指令。端口可访问或协议探测通过不代表 QQ 已完成双向收发验收。运维测试不得主动给真实群发消息。

## 运行边界

管理端口默认只监听服务器本机，需通过已有受保护管理通道访问。定时主动开口默认关闭；普通群聊自主接话继承已确认配置。陌生人私聊只交给原绑定流程。模型费用走配置的 API 凭据。桥使用持久化计数器限制成员、群和全局每日调用、自主接话每日调用及每小时/每日回复；接管当天可导入原站点计数作初始额度。这些计数不回写原站点聊天统计，站点 API Key 自身的费用/额度约束继续生效。

当前工具清单不包含通用联网搜索或本地文件操作。图片由 AstrBot 从 QQ 的 HTTPS 媒体域名读取并作为内联附件送给 DSH；生图、站点只读查询和资金指令继续在原业务处理路径中。表情包生成或 DSH 的模型工具扩展应单独按权限接入。
