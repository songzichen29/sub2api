# QQBot 独立运行环境

链路：NapCat → OneBot 分流 → AstrBot → DSH SDK → 已授权模型 API。签到、余额、绑定、转账、抽奖、图片业务及通知仍由原 Sub2API 执行；分流器保留原 OneBot 反向连接和 API 回执。

## 发布与部署

生产分支的 `Build QQBot Runtime` 构建独立 `qqbot-runtime` 镜像。等待构建成功，核对 OCI revision 后按摘要部署。`compose.example.yaml` 是部署模板；真实令牌只在服务器受保护文件里维护。模型、基础人格、群权限和接话策略保存在站点配置；回复方式、音色和会话人设还可由获准私聊用户通过聊天修改，不提交到 Git。

后台「群聊、记忆与欢迎 → 与机器人私聊」独立配置私聊开关和允许的 QQ 号。关闭时保留名单，空名单不开放；群管理员身份不再自动授予私聊权限。升级旧配置时仅保留原已允许的管理员名单，显式保存后不再继承。白名单用户可使用聊天、语音、联网、表情包、生图与原图编辑，也可在私聊中管理回复设置；各功能开关及额度继续生效，绑定流程独立保留。私聊生图使用原站点持久队列，按发送者与消息去重，共用站点总额度和个人额度；不占群额度、不写群历史，仅向原发送者私聊发图。排队执行、额度预留和发送前再次校验私聊权限，QQ 回执缺失不会自动重发。

复制本次提交的 `astrbot_plugin` 到模板指定的 `source/astrbot_plugin`，只读挂载。服务状态、配置和会话分别持久化，更新镜像不能删除数据目录。保留上一个镜像摘要、NapCat 配置及当前 Compose 以便回滚。不要运行 `docker compose down -v`。

桥通过 HTTPS `/api/v1/qq-bot/runtime/config` 获取后台已保存配置，Bearer 使用原 OneBot token，并校验 X-Self-ID。每 10 秒拉取并上报状态；45 秒未成功同步时拒绝新聊天。密钥不出现在 `/policy`、`/health` 或公开管理配置中。DSH 子进程只得到模型密钥及必要启动变量，QQ 专用 profile 没有命令、文件、插件管理和子 Agent 工具。模型或人格变化会换会话并保留公开聊天记忆。

`config/config.json` 只保留部署信息，例如：

```json
{
  "bot_id": "1849138657",
  "site_config_url": "https://api.dwai.cloud/api/v1/qq-bot/runtime/config",
  "business_ws_url": "wss://api.dwai.cloud/api/v1/qq-bot/onebot/ws"
}
```

启用前在站点保存 `runtime_chat.enabled=true` 并迁移当前有效模型、协议、Key、人格、白名单和额度。保存后旧 `autonomous`、`history_messages`、`meme_enabled` 不再持久化或公开，旧聊天任务和旧模型测试入口停止执行。升级旧配置时不可把旧聊天型号误当成当前 DSH 的可用型号。

后台 `chat_protocol=responses` 对应 DSH `openai-responses`，`chat_completions` 对应 `openai-completions`。模型列表可见不代表视觉能力可用，须通过目标模型请求核验。模型上下文容量填写真实支持的 tokens 数，默认 65536；它不是聊天记录条数上限。

群内完整的本人余额、今日用量、抽奖次数查询不需要 @ 或斜杠，例如“查下我的余额”“我让你查下我的余额”。由站点按消息发送者的绑定查询，保留原文，不调用聊天模型。一般讨论（如“余额是什么”）、他人账户、否定句及混合转账请求不自动变成账户查询。查询语法需与后端 `natural_account.go` 保持一致。

先部署支持 `sub2api_observe_only` 的 Sub2API，再启用 `business_observation: true`。开启后白名单群的聊天及仅 @ 其他人的消息也送给原站点，保留防刷、群记录和图片引用；观察消息不创建聊天或业务任务。业务指令仅执行一次。旧版站点未支持此标记时禁止开启。

分流器通过认证 `/runtime/ingress` 查询真实绑定会话和防刷屏结果，再向业务或聊天转发。绑定中的所有私聊（含短绑定码和“取消”）交给绑定流程；没有绑定会话时，`OpenAI`、`DeepSeek`、`确认一下今天的天气` 等普通消息正常聊天。入口检查失败明确记录并停止转发，不把绑定内容交给模型。指定私聊白名单成员也可查询本人余额、今日用量、抽奖次数：账户数据由站点直接私发，不进入聊天模型或共享记忆；发送前再次检查白名单和绑定。私聊不会因此开放签到、抽奖执行或转账。

站点两个业务处理槽分别保留给生图和其他业务，避免两个长时间生图任务同时占满处理槽。生图并发改为一个，短业务保留一个槽；同成员的在途任务仍保持顺序。已有去重、队列容量和回复期限不变。

## 会话和投递

### 在私聊中设置长期回复规则

现有私聊白名单用户可在私聊中管理所有已开放群的音色、回复方式和人设，无需另一份管理员名单。群内消息不开放这项管理能力，账户与资金权限保持原样。关闭私聊或移出白名单后，管理权限同时取消。查询和修改的来源身份取自真实 QQ 消息，目标群单独指定，只能选择当前 Bot 的已开放群。

可以直接说：

- `有哪些音色？以后跟我聊天用御姐语音。`
- `A 群和 B 群以后都用曼波语音，工作群继续用文字。`
- `给 A 群加一条要求：回答先给结论，简短一点。`
- `A 群现在是什么回复设置？把它恢复成共享默认。`

模型在原聊天回合中使用 `list_voices` 查询已接入的音色目录，使用 `list_reply_groups` 查询已开放群号和配置备注，再通过 `get_reply_settings` 读取规则与版本、`update_reply_settings` 保存本次变更。群名不清或重名时询问群号，不猜目标。未指定范围时只改当前私聊；明确要求所有群时才改群共享默认。仅切换音色不会同时开启语音，要求“以后用这个音色说话”时才一起保存语音回复方式。

长期设置保存在站点配置的独立 `reply_settings` 字段和 `reply-settings` 分区中：`group_defaults` 为群共享默认，`groups` 为群单独覆盖，`private_users` 为各自私聊覆盖。管理工具只查询和修改调用者自己的私聊规则，不返回其他用户的私聊规则。未设置的字段继续继承；群单独设置覆盖共享默认，后来开放的群也会继承共享默认，私聊不继承群规则。后台保存聊天开关、群权限或旧版完整配置时，不会覆盖这些独立回复规则。回复规则通过私聊管理工具修改，不开放通用后台分区写入，确保所有音色选择都经过实际目录校验。

本条明确的临时要求优先于已保存设置，例如 `这次用文字` 只影响当前回复；`以后用文字` 则保存长期规则。没有已保存规则时默认文字和默认音色。聊天历史、摘要、引用及网页中的指令不作为正式设置；普通聊天继续使用已保存设置，不要求模型每轮重新选择语音。Prompt 支持 `replace` 替换、`append` 在当前有效人设后追加并保存为该目标覆盖，以及通过 `reset` 删除覆盖、恢复继承；显式空 prompt 与恢复继承不同。公开站点知识和程序权限规则仍独立保留。

同一句涉及多群和例外时，在一次事务中保存全部修改，任一目标或参数无效则全部不变。保存使用查询得到的版本，版本冲突明确报错，不自动重试；操作编号绑定真实 QQ 消息，同一回合提交后只允许查询结果，不能更换工具调用编号再次写入；旧版本请求不能重复追加人设。变更沿用现有配置历史并记录 QQ 操作者。保存成功后立即刷新运行时配置，后续聊天回合应用新规则，设置操作的确认固定用文字报告实际保存和同步状态；已保存但同步失败时明确提示查询确认，不把同步失败当作未保存重新追加。人设变化会更新受影响会话的系统提示并保留聊天记忆。

### 在私聊中让 Bot 去指定群发消息

现有私聊白名单用户可以直接说：

- `去 A 群发一条文字：今晚八点开会。`
- `去 A 群用御姐语音说：大家晚上好。`
- `帮我写一句欢迎语，发到群 123456789，按这个群平时的方式发。`

模型通过 `list_reply_groups` 确认目标，再调用 `send_group_message`。群名不明确或重名时先问群号；目标必须已开放且允许聊天。只发送用户指定或要求撰写的正文，不转移私聊历史。未指定方式或音色时继承**目标群**的设置，临时指定不修改长期规则，普通私聊仍沿用自己的回复方式；发送操作的确认固定使用文字，不再合成一条私聊语音。同一条请求向同一群的内容合为一次发送。

跨群发送复用分流器现有 OneBot 连接；内部接口仅允许带桥令牌的群文本、语音发送，不开放任意 QQ API。来源私聊、目标群权限在发送前重新检查。发送记录持久化，并按真实来源消息和目标群去重，更换模型工具调用编号不会重复发送。语音先完整合成，再逐段发送和保存实际 QQ 消息 ID。只有完整回执才返回成功；部分发送、断线、缺回执均如实报告，不自动重发。目标群记忆只记录确认发出的内容，不包含私聊管理指令。目标群已发送但私聊确认生成失败或超时时，按持久记录报告实际状态；状态查询也失败时明确提示先核对目标群，不建议直接重复提交。

发送和设置工具一旦被尝试，本轮最终回复由程序根据持久操作结果生成，不采用模型编造的成功话术；查询群列表成功不会覆盖发送失败。同轮查音色、群列表或回复设置时，确认中保留工具返回的真实目录与设置摘要；设置摘要注明查询时状态，不把修改前的值冒充保存后的当前值，也不复制完整人设和站点知识。纯查询仍沿用正常聊天回复方式。发送前校验拒绝同样保存为失败记录，保存设置与发送消息分别报告。结果表仅保存目标、方式、音色、字段类型和状态，不保存待发正文或人设内容。超时、重启及重复收到同一 QQ 消息时只查询真实结果，不重放操作；仍在执行或响应丢失时明确显示未确认。操作回合不保留包含模型未交付答复的会话，下轮从已交付结果恢复上下文。

普通群成员可在当前群要求 `有哪些音色？`、`用御姐语音回答我`、`这次只发文字`，只影响本条回复。跨群发送、修改群默认音色/回复方式/人设须由白名单用户在**私聊**中操作；群管理员身份或在群里自称管理员不会放开这些权限。

发布这项能力需同时更新 `qqbot-runtime` 的 bridge、router 及 AstrBot 挂载的 `astrbot_plugin`。沿用现有内部网络、桥令牌与 SQLite 数据目录，无需新增管理员配置、依赖或 Sub2API 数据库迁移。

### 文字转 QQ 语音

在已开放群或原本允许的私聊中发送 `御姐语音合成 你好，欢迎加入`、`御姐 语音合成 你好`、`/曼波语音合成 你好` 或 `语音合成 你好`。音色与“语音合成”之间允许空格。普通聊天按已保存回复设置执行，未设置时默认文字；目前不进行语音识别。命令不调用聊天模型，沿用聊天权限、冷却和调用额度；关闭表情包或图片发送不影响语音，关闭聊天会取消语音投递。

使用未接入的音色（如 `喜羊羊 语音合成 灰太狼来了`）会直接提示真实可用音色，不调用模型或合成服务，也不擅自换成默认音色。`不要语音合成`、`语音合成是什么` 等否定或讨论不作为执行命令。音色查询以 `list_voices` 当前目录为准，旧聊天里的音色名称不作为可用依据。

引用当前群或私聊中的一条文字消息后，发送 `语音合成` 或 `御姐语音合成`，会朗读被引用的文字；命令后有正文时优先朗读正文。引用读取失败、无文字或超过现有引用读取长度时明确报错，不猜测内容或朗读被截断的片段，引用中的敏感信息同样禁止提交第三方。

也可以直接说 `用语音回复我，为什么天空是蓝色的？`、`今天怎么样？请用语音回答我`、`用御姐的声音回答我，讲个笑话` 或 `给我发条语音吧`。此时先由聊天模型理解当前问题及引用上下文，再把实际回答合成 QQ 语音；不会把用户的问题直接朗读一遍，也不会只输出“已发送语音”等占位文字。直接语音请求按直接互动处理，不受群自主接话采样影响，原有权限与额度继续生效。当前明确要求覆盖已保存的回复方式，未指定音色时沿用当前会话的有效音色。仅讨论语音功能不改变设置，明确拒绝语音或改用文字时本轮发文字。合成失败明确报错，不自动改发文字。语音回答只发送音频，答案正文在全部 QQ 发送回执确认后进入会话记忆。

`这段话念给我听`、`把引用的内容读给我听` 会直接朗读引用原文；`请朗读：你好`、`把“你好，世界。”念给我听` 会直接朗读指定文字。这类朗读和固定“语音合成”命令都不调用聊天模型。不指定音色时使用 `fbe02f8306fc4d3d915e9871722a39d5`；指定音色时保留文档原有映射。

`今天的天气用语音回答我`、`今天星期几  用语音回答我`、`我不方便看屏幕，能说给我听吗` 及引用后只发 `语音`，都会进入同一次模型回合，结合当前请求和引用调用 `set_reply_mode` 选择语音，不额外调用分类模型、不要求特定标点。该工具只设置本条输出方式，长期要求通过上述管理工具保存；历史或引用里的要求本身不授权切换方式。最终答案仍须真正合成并取得 QQ 回执。模型最终仅输出“调用 set_reply_mode 选择 voice”等内部操作步骤时，会明确报告未生成实际正文，不朗读步骤、不自动重试；用户明确指定朗读的原文或询问工具 API 的正常回答不受这项检查影响。收到用户发来的语音不会把空文本提交模型，会明确提示尚不支持语音识别。

在已开放群或允许的私聊中戳机器人，会由聊天模型结合该会话的上下文生成回复，并沿用权限、调用额度、排队、去重和 QQ 回执流程。戳他人、机器人自己触发和未授权会话不调用模型；戳机器人按直接互动处理，不受自主接话的采样或活跃时段限制，其他 OneBot 通知仍交给原业务服务。

命名音色与 ID 取自[指定接口文档](https://docs.apipost.net/docs/detail/6d449f2cd470000?target_id=140a868932c004)，统一保存在 `src/voice-catalog.json`，包括可莉、塞恩、猫咪、妮蔻（Nico）、盖伦、御姐、刘亦菲、蒋介石、军事、曼波、贝利亚、蔡徐坤、麦克阿瑟、影视解说、宣传片、曹操、乌萨奇、卢本伟、泽拉斯、派克、雷军、爱莉希雅、空之律者、典韦、鳄鱼和李云龙。`list_voices` 返回这份当前已接入目录，不自动发现上游新增音色；查询、切换校验和合成都使用同一份名称与 ID 映射。固定合成命令省略音色时使用用户指定的默认 ID `fbe02f8306fc4d3d915e9871722a39d5`；显式指定可莉等音色仍使用各自原有 ID，多个 ID 的命名音色固定选第一个，不在失败时切换音色。

桥将命令后的文本或实际回答提交到 `POST https://video.chrelyonly.cn/video-api/getVideo`，JSON 为 `{"text":"你好","referenceId":"8a88ef7d77d748e59879d8994e216e01"}`。本次要求或长期设置使用语音时，该第三方会收到待朗读文本，不携带站点或模型凭据。每次最多500个 UTF-16 字符，长文完整顺序分片且不拆开 emoji；所有分片生成成功后，再以独立 OneBot `record` 消息逐段发送。

接口文档没有成功响应结构，目前只接受可识别的 MP3/WAV 二进制响应；JSON（包括 URL/Base64 对象）、HTML、空响应及超过6MiB的单段音频均明确报错，不猜测字段、不跟随重定向、不自动重试。文档未列出可用鉴权信息，调用不附加凭据。2026-11-19 经授权用御姐音色合成“你好”一次，实际返回 HTTP 200、`Content-Type: audio/mpeg`，音频16717字节。其他音色及 QQ 实际转码播放尚未验证。

复用现有媒体持久化、投递领取和逐段回执。只有收到每段 QQ 消息 ID 并完成投递才在共享历史记为“已发送语音”；部分送达、断线或回执不明不重发。同一条 QQ 消息重复到达时不重新生成或重复发送。发布长期回复设置时，先更新支持独立配置分区和管理工具的 Sub2API 后端，再更新 `qqbot-runtime` 镜像及 AstrBot 挂载的 `astrbot_plugin`；无需新增依赖或修改 Sub2API 数据库结构。

同一个群的公开聊天按机器人和群共享，记录 QQ、昵称与时间，能结合多人的发言；不同群和私聊相互隔离。SQLite 和 raw JSONL 持续保存原文，没有固定条数或年龄截断。达到模型容量预算时，先成功保存摘要再推进游标，后续通过摘要和同群原文检索继续会话。完整原文不可能同时塞入有限的模型上下文。业务查询、绑定、密码及模型密钥不进入公共聊天记忆；助手回复只有确认送达才进入公共历史。

升级会导入旧分成员的群记忆；私聊不会导入群，未确认送达的助手回复不导入。`/清空` 重置该群活动上下文和检索（只允许本站配置的该机器人/该群管理员或当前 QQ 群管理员），私聊自行重置；审计原文和明确收藏保留。群管理员不会因此获得其他群的清空权限。DSH 会话只有收到完整 QQ 发送回执后才成为下一轮可恢复的会话；被限额、取消、部分发送或未确认的回答不进入模型会话记忆。旧回合的迟到回执不会覆盖新回合会话。

欢迎由站点处理已开放群的真实入群事件：提及新成员、支持 `{name}` / `{qq}` / `{group}`，不调用模型。重复、超过 10 分钟、机器人自身和关闭通知的群不发欢迎，发送未确认不重试。不自动接入新群，也不扩大白名单。

同群按顺序处理；不同群/私聊最多四个独立 DSH 进程并发，每个进程使用独立目录和绑定当前会话的工具令牌。同会话在 AstrBot 最多32条等待/处理中消息，桥最多64条等待消息。225秒期限包含下载、排队和模型处理；客户端取消或排队过期后不再启动模型。重复消息复用已完成结果，中断与失败不自动重跑。模型达到输出上限但已返回文字时保留文字并标明未完整；摘要不接受截断结果。

AstrBot 在发送前持久领取投递标记，并重新核对当前群、聊天和图片发送权限。回复首段引用原消息；每段独立保存 QQ 回执，只有所有段成功才记为送达，部分成功或中断保留已有回执且不自动重发。准备好图片但没有最终文字仍可发送。分流器不重放 QQ API 动作。上游暂时不可用时分流器记录计数并丢弃当时事件，不自动补执行资金操作；必须查看健康接口和实际消息记录。

全套健康检查包括桥 8787、AstrBot 6185、分流器 6200、原 Sub2API OneBot 连接，以及用户在允许群发出的一次真实聊天/站点指令。端口可访问或协议探测通过不代表 QQ 已完成双向收发验收。运维测试不得主动给真实群发消息。

## 运行边界

### 指定时点热群与北京时间

后台“群聊、记忆与欢迎 → 指定时点热群”设置 `runtime_chat.proactive_enabled`、`proactive_groups`、`proactive_times` 和 `proactive_idle_minutes`。时间点按北京时间 HH:MM 填写，不需要填写 cron；默认提供 12:00、14:00、18:00、21:00，开关默认关闭且不自动选择新群。热群与普通接话开关独立，群权限、全局/群额度和群接话额度继续约束热群，不使用最后说话成员的身份或个人额度，也不执行账户与图片工具。

到点由 DSH 结合本群共享上下文和时段生成简短话题，并沿用本群已保存的人设、回复方式和音色；语音模式下即使没有文字正文，AstrBot 也会发送返回的音频。主动热群不获得私聊配置管理权限。指定安静时长内有群成员发言则跳过；生成期间有新发言、群被禁用或配置关闭，投递前取消。时点按机器人/群/北京时间日期去重持久化，生成或投递不明不重试；重启不补发早于启动分钟的时点，生成超过五分钟也不发送。AstrBot 每 15 秒检查，可在没有新消息或重启后工作；QQ 发送必须保存实际消息回执。忙碌、模型跳过、生成、取消和投递结果通过结构化日志及 `proactive_slots` 记录。

模型当前时间、群历史、检索原文和摘要输入统一为 `Asia/Shanghai`、带 `+08:00` 的时间。审计原始数据仍按 UTC 保存。系统时间规则明确普通口述时间默认北京时间，不因底层 UTC/Z 时间戳再次加八小时；新规则会更新 DSH 会话身份，保留原始记忆。

管理端口默认只监听服务器本机，需通过已有受保护管理通道访问。定时主动开口默认关闭；普通群聊自主接话继承已确认配置。陌生人私聊只交给原绑定流程。模型费用走配置的 API 凭据。桥使用持久化计数器限制成员、群和全局每日调用、自主接话每日调用及每小时/每日回复；接管当天可导入原站点计数作初始额度。这些计数不回写原站点聊天统计，站点 API Key 自身的费用/额度约束继续生效。

DSH 的聊天工具包括 `set_reply_mode`、`list_voices`、`generate_image`、`edit_image`、`web_search`、`web_fetch`、`send_meme`、`collect_meme`；回复配置工具为 `list_reply_groups`、`get_reply_settings`、`update_reply_settings`，仅允许私聊白名单用户在私聊中执行。不提供命令、文件或通用站点管理工具。自然语言画图和原图编辑经认证 `/runtime/tools` 进入原站点任务队列，以原 QQ 消息 ID 去重，沿用生图配置、额度和真实发送回执。编辑携带经过格式/大小校验的原图，使用 images/edits；原图缺失或编辑失败不回退为文生图。工具的 queued 仅表示受理，不表示出图。升级先发布站点后端，再更新桥镜像和 AstrBot 挂载的插件目录。

路由记录和转发按群、私聊分别串行，不再由一个慢群阻塞所有群。225秒期限从路由接收开始计算。受防刷屏管理的群在模型执行、工具执行和投递领取时重查原消息，生成期间被拦截的消息不再投递。工具错误及配置同步错误记录固定错误码、HTTP状态和失败阶段，不输出上游正文、聊天内容或凭据。

联网查询通过站点访问公开来源，返回来源 URL 与检索时间；网页不携带站点凭据，DNS 和各次重定向均校验公网地址。来源失败必须如实说明。后台 `runtime_chat.web_enabled`、`memes_enabled`、`collect_memes` 独立控制能力，不恢复旧自主接话设置。

表情包先匹配本会话收藏和24小时搜索缓存，再访问现有公共搜索来源；搜索及换词回退合计最多60秒。公共来源仍可能不可用，随机请求可使用本会话收藏兜底，精确关键词不擅自替换成不相关图片。搜索结果缓存与人工收藏分开，自动再次收集不会覆盖人工标签。

收藏/编辑优先当前消息原图，再明确引用；都没有时仅允许当前发送者最近10分钟的图片。当前图或引用下载失败绝不换用其他成员的图。每次最多4张、单张6MiB、合计12MiB，保留原消息编号，超过限制需分批发送。关闭看图只禁止向模型转发图像，明确收藏普通照片和原图编辑仍可下载工具附件；模型不能声称看过这些工具附件。引用携带原消息ID、作者和文字；私聊只读取同一对话的消息，机器人发出的私聊引用必须有该会话的发送回执。GIF原始字节保留，不声称视觉模型理解了完整动画。

临时原图和搜索缓存分别保留24小时且各不超过128MiB；终态发图资产最多7天，发送资产总量上限256MiB，容量回收只移除终态资产，未决发送不被挤出。收藏上限1GiB，满后停止添加而不自动删除用户收藏。运行诊断保留30天；原始聊天审计保存策略不变。

后台概览、聊天配置和“运行记录 → 聊天记录”展示桥上报的调用、确认送达、失败、未确认、排队和运行数，以及最近20条状态/原因。45秒未同步或跨北京时间日期后指标标为未知，不显示为零；业务任务仍有独立记录。日志和状态上报不包含聊天正文、原图、模型答案或凭据。
